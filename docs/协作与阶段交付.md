# 协作与阶段交付

本文是两位协作者和后续执行者的操作入口。最新状态见 CONTEXT.md 顶部，任务归属见 TASKS.md，约束见 COLLAB.md。

## 一次性准备

双方接受仓库协作邀请，各自使用独立目录。已有写入权限时直接使用仓库任务分支。main 是审核后的共享版本，每项任务创建一个短期分支；不需要额外维护永久的个人分支。

首次在 Windows PowerShell 中执行：

```powershell
git clone https://github.com/Aa144085412/Study-companion.git
cd Study-companion
```

仓库所有者可为 main 设置必须经 PR 和至少一位其他协作者批准的保护规则。本会话没有仓库管理权限，未修改该设置。

## 每次任务

工作区干净时，先同步 main，再读接手文件、确认任务归属：

```powershell
git status --short --branch
git switch main
git pull --ff-only origin main
git log --oneline -15
```

TASKS.md 中 owner 使用能区分两人的名字或账号，写明 branch、files、验收方式。先通过 Issue、PR 或约定沟通渠道同步认领，再创建自己的任务分支。本地认领尚未上传时，对方看不到。

```powershell
git switch -c feat/your-name-task
```

## 每阶段记录

每阶段保持代码、说明与验证结果一致。使用以下格式更新 CONTEXT.md 顶部和任务条目；不要把待验证内容写成已完成。

```text
任务 / 阶段：T编号 / 阶段名称
owner：可区分执行者的名字
branch：任务分支
范围：本阶段实现的行为与涉及文件
验证：命令、实际结果；模拟与真实验证分别写
未验证 / 已知边界：明确缺失的环境或功能
上传：未提交 / 本地提交 / 已推送并核对远端；PR 链接
下一步：下一位可直接执行的操作
```

执行相关检查后，逐个暂存本任务文件，再 commit 和 push。用户明确授权阶段上传后，该授权在任务范围内持续有效。遇到网络、账号权限或连接器授权错误时保留本地提交，报告具体错误，不重复提交或宣称远端成功。

## PR 与接续

在 GitHub 创建 PR，base 选 main，compare 选任务分支。PR 写清问题、改动结果、验证与限制；由另一位协作者审核。后续阶段继续提交到同一分支、更新同一 PR。合并后双方拉取 main。

如果自己的任务尚未完成，先提交当前改动，再同步主线到当前任务分支：

```powershell
git fetch origin
git merge origin/main
```

解决冲突后重新验证，再推送。没有冲突也要确认组合后的功能正常。
