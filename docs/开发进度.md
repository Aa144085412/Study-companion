## 2026-10-09 · M1 材料与来源验收（代码已具备，本轮跑验收）

M1 核心功能（任务队列、转写校对版本、哈希去重、引用定位原媒体、持久化）在 v0.2 代码中已实现；本轮用真实长音频（`tests/fixtures/long-zh.mp3`，71.9s，edge-tts 生成，生成器 `tests/make_long_audio.py`）逐项跑验收：

- **A02 任务恢复**：上传长音频→建转写 job→执行中杀服务器→重启后 job 落 `interrupted`（提示"服务已重启，请点击重试"）→retry 后 `completed`，生成转写来源。通过。
- **A03 转写校对版本**：对转写来源（revision 1，14 段）做真实校对（改错字，片段数/id 不变）→生成独立 revision 2（`previousId` 指向原版）、原版保留且 `replacedBy` 指向新版、内容不同；再校原版被 409 挡（"该版本已有校对稿"）。通过。
- **A05 来源完整性**：提问"热激目的/为何冰浴"→4 条引用 `[S1..S4]` 全部有效（无"引用无效待核对"）、每条 `sourceId` 均能定位到笔记本内真实来源。通过。
- **A06 回放位置（API 级）**：转写段引用带 `start/end` 毫秒时间 + `mediaId` 指向原媒体，媒体经 `/api/media/{id}` Range 可回放（206）。通过。（"10 个手工选取片段"的纯 UI 操作本轮未做，记为边界。）
- **A12 持久化**：重启前/后 `/api/state` 规范化快照字节级一致（notebooks 3 / sources 5 / revisions 2 / messages 8 / jobs 1）。通过。
- 回归：Node 测试 6/6 通过（含 dedup/校对/取消/重试/重启 interrupted 等），语法检查通过。

- **长音频/视频导入转写（已活体验证）**：250MB 流式上传上限（mp3/wav/m4a/mp4/webm/ogg），实测 71.9s 音频冷转写 ≈10.7s（约 9× 实时，1 小时音频约 6–7 分钟，远低于 2h 任务超时）；mp4 视频经 PyAV 抽取音轨端到端通过（73.8s→12.4s、16 段）。唯一已知限制：任务中断后重试从头转写，无断点续传。
- **发现缺口：无删除能力**（笔记本/来源在 API 与 UI 均无删除入口），本轮 M1 测试数据由脚本清理；后续应补删除功能。

M1 状态：**核心验收通过**，可视为 M1 基本收口；余量为 A06 的手工 10 片段 UI 复核（可在真实使用中顺手完成）。
