# 视频总结标准 SOP

适用于抖音、小红书视频与 B 站视频 URL。沿用现有 Node/Python/Pydantic 及审计管线，不把抽帧、ASR 完成或模型返回文字当作整个任务完成。

## 标准入口

使用 `POST /api/agent/media`，提供 `source`、`url`、`goal`；知识总结指定 `skillKind: knowledge`。`POST /api/agent/tools` 的视频分支也委派同一个 URL 驱动，不能让工具选择跳过 OCR。旧同步 `/api/tools/loop` 对视频返回 409，并提示标准入口；非视频图文工具循环保留。

1. 下载视频和音轨，记录标题、作者、URL、时长。缺视频或音轨即失败。下载器的少量预览帧不构成画面识别证据。
2. 把**视频**上传到持久化媒体队列，复用同本同文件哈希已有转写；完成带时间片段的 ASR。保留原始识别，不按猜测改写。
3. 调用已有 `visual-review`：每个 ASR 片段中点抽样，执行 OCR，分开保存上下区域文字候选；必要时做有预算的本地视觉补充。保留帧时间、原图、置信度和推断标识。字幕区域是启发式，不能把底部所有文字都视为真正字幕。
4. 等待画面任务完成，检查抽样数、导入来源和可用视觉证据。无视觉证据或处理失败必须停止，不能静默降级成 ASR 摘要。部分未识别帧、VLM错误和覆盖局限如实保留在报告中。
5. 后台启动现有审计笔记生成并轮询状态，避免旧驱动 180 秒同步超时。使用结构化 ASR/OCR/视觉证据，执行证据清洗、事实综合、归因审计和分层渲染；语义复核的引用必须包含来源ID和原句；格式错误只允许有限重试，持续错误仍待核对，有效的负面判断不得为了通过而重试。Pydantic 验证后保存带 `auditPipelineId` 的版本。**不要再 POST 普通 `/api/notes` 复制一次结果**，以免丢失审计元数据。
6. 读取当前 `/api/audit` 和实际保存版本，确认审计未过期、存在事实、视频审计证据确实包含画面模态。知识包使用 `auditedOnly: true`，直接封装该版本，保留分层、来源与待核对项，不能再让模型从原始转写重新生成未经审计的知识。
7. 总结请求不替用户出题/作答；需要练习时才调用既有 quiz_engine 核心白名单与盲解验证。
8. 验收报告记录各步、媒体与视觉任务 ID、审计版本、画面证据数、知识包路径及错误。任一必需步骤失败均返回非零并标 failed，只有所有产物校验完成才能标 done。

## 缓存与重试

`url_pipeline.py --resume-media <download-result.json>` 可复用当前下载，必须匹配来源 URL、平台并有真实视频和音轨。只用于本机可信下载结果；不是任意远程路径导入接口。ASR、OCR 和审计调用沿用已有缓存，仍执行状态与产物门禁。超时保留已完成证据，不声称完成，也不自动切换云模型。

## 发布门禁

新增顺序/失败拦截/过期审计/审计包测试，运行原项目 Node 与 Python 回归和语法检查。使用当前真实视频完成 OCR→联合证据→审计笔记→知识包，并核对关键帧与结论、引用及待核对项后才提交。测试成功不等于全部画面已覆盖，也不是独立权威事实认证。提交只含代码、测试、说明与脱敏验收记录，不含视频、用户数据库、Cookie、模型或环境。
