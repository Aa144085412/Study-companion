# 研习伴模块项目计划书

> 从记录到理解，从理解到实践。

- 文档版本：v0.1
- 编写日期：2026-10-09
- 项目状态：规划完成，尚未开始部署与开发
- 目标宿主：科研工作台；第一阶段允许独立原型验证
- 文档用途：指导需求确认、技术验证、分阶段开发与验收

## 1. 项目定位

研习伴是面向科研学习和实验技能理解的 AI 学习模块。它将录音、视频、实验规程、参考文献和个人笔记关联起来，支持整理笔记、共读材料、语音提问、来源回溯和复习巩固。

核心体验：用户打开某个实验的笔记，选中不理解的段落，按住说话提问；AI 根据当前段落、上下文和相关材料解释，并提供可核对的来源。用户可以继续追问、回听原始讲解，将确认后的理解保存到笔记中。

模块辅助理解、复习和准备实验。学习记录反映理解进度，不自动认定用户已经具备独立实验操作能力。

## 2. 目标与成功标准

### 2.1 项目目标

1. 将分散的音视频和文档转为可查阅、可追溯的学习资料。
2. 降低提问成本，支持围绕当前阅读位置连续语音交流。
3. 区分原始记录、整理笔记、AI 补充解释和用户确认内容。
4. 保存疑问、理解过程与复习结果，形成长期学习积累。
5. 在验证有效后接入科研工作台，复用适合的现有能力。

### 2.2 首个验证场景

以“酵母转化学习”为示例笔记本，收录一份经授权使用的讲解录音或视频、一份实验笔记，以及可获得的确认版实验规程。围绕实验目的、步骤原理和材料中明确记载的注意事项进行共读。

现有手写笔记中不清晰的浓度、体积、时间及试剂名应列入待核对项，不直接作为确认版规程。

### 2.3 第一版成功标准

- 能完成“导入材料 → 转写 → 校对 → 生成笔记 → 选段语音提问 → 查看来源 → 保存疑问”的完整流程。
- 回答能识别用户当前选中的段落，并支持同一会话内的连续追问。
- 引用能打开对应资料；涉及录音的引用能定位到已保存的时间范围。
- 无法从材料确定的参数明确标为待核对，不自动补齐。
- 重启应用后，资料、笔记、会话、来源关联和待复习内容仍可恢复。
- 外部模型不可用时保留已有成果，错误可见且任务可重试。

## 3. 用户场景

| 场景 | 用户操作 | 预期结果 |
|---|---|---|
| 整理讲解 | 导入录音、视频或已有字幕 | 获得带时间戳的转写稿及待校对内容 |
| 建立笔记 | 从已校对的转写稿生成实验笔记 | 按目的、原理、步骤、参数、注意事项、疑问组织 |
| 共读提问 | 选中文字后说“这一步为什么这样做？” | 回答围绕选中内容，显示依据 |
| 连续追问 | 接着说“我还是没懂，举个例子” | 沿用当前讨论主题，换一种解释方式 |
| 核对来源 | 点击“查看原讲解” | 播放对应音视频片段 |
| 保存理解 | 将有价值的回答加入笔记 | 用户预览并确认修改，保留来源及历史版本 |
| 复述练习 | 口述实验目的和步骤 | 对照指定材料指出遗漏、混淆和待确认内容 |
| 后续复习 | 打开未解决问题列表 | 从原段落继续学习，记录理解变化 |

## 4. 范围与版本规划

### 4.1 P0：第一版必须实现

- 学习笔记本：按实验或主题组织资料。
- 本地文件导入：首批支持 MP3、WAV、M4A、MP4、TXT、Markdown、SRT；视频处理范围为音轨。
- 异步转写：任务状态、进度、错误原因、重试和取消。
- 转写校对：文字可编辑，原始识别结果与校对稿分别保留。
- 结构化笔记：生成草稿、人工修改、确认保存。
- 共读界面：笔记、问答和原始媒体播放器。
- 按住说话：录音转文字、确认或修改问题、发送、文本回答。
- 回答播报：可关闭、可停止；播报失败不影响文字阅读。
- 当前段落上下文：显式传递选区、段落与笔记版本。
- 来源引用：材料定位、原音视频片段回放。
- 疑问记录：未解决、学习中、已理解三种状态。
- Markdown 导出：保留来源标识和时间范围。
- 本地持久化与备份恢复。

### 4.2 P1：第一版稳定后实现

- PDF 文本导入与页码引用；优先复用宿主已有可靠能力。
- 扫描 PDF、手写笔记 OCR，识别结果必须支持校对。
- 术语表：试剂、缩写、英文术语及经确认的写法。
- 多人录音说话人区分。
- 复述练习、知识点卡片和复习队列。
- 笔记变更对比、引用失效检查及跨资料冲突提示。
- 视频关键帧、PPT 和板书内容提取。
- 可选全文与向量混合检索。

### 4.3 P2：后续增强

- 支持打断、端点检测与回声处理的连续语音对话。
- 手机访问与跨设备同步。
- 跨实验知识关联、个性化复习安排。
- 更丰富的交互图解和操作前复述练习。

### 4.4 第一版不包含

- 从视频画面自动判断实验操作是否规范。
- 自动生成并认可缺失的实验参数。
- 自动修改确认版实验规程。
- 实验设备控制、自动执行实验。
- 多用户协作、公开分享和云端同步。

## 5. 技术选型与 GitHub 项目

以下项目能力依据 2026-10-09 查阅的官方仓库说明整理，尚未在目标机器上进行组合实测。正式采用前应固定版本或提交号，检查许可证、依赖、硬件要求和实际接口；README 中列出的能力不等于已经完成本项目验收。

| 项目 | 项目角色 | 使用建议 | 需要自行补齐 |
|---|---|---|---|
| [Buzz](https://github.com/chidiwilliams/buzz) | 带界面的音视频转写工具 | 原型阶段生成文稿和 SRT，验证识别效果 | 自动任务管理、与笔记来源关联 |
| [Open WebUI](https://github.com/open-webui/open-webui) | 文档问答、笔记及语音交互界面 | 优先用于快速验证“材料＋语音问答”体验 | 精确阅读选区、原音频定位、专用学习记录 |
| [Open Notebook](https://github.com/lfnovo/open-notebook) | 资料与笔记管理、基于来源问答 | 作为资料管理优先时的备选；提供 REST API | 实时语音共读不能视为已具备完整能力 |
| [faster-whisper](https://github.com/SYSTRAN/faster-whisper) | 本地转写引擎 | 自动化长音频处理的首个候选 | 任务服务、导出与异常处理 |
| [FunASR](https://github.com/modelscope/FunASR) | 中文语音识别及相关组件 | 与 faster-whisper 用真实录音比较后选用 | 所选模型的时间戳、术语与部署能力需验证 |
| [CosyVoice](https://github.com/QwenAudio/CosyVoice) | 语音合成 | 需要本地中文播报时评估 | 服务封装、流式播放和宿主接口适配 |
| [Pipecat](https://github.com/pipecat-ai/pipecat) | 实时语音应用框架 | P2 连续对话阶段评估 | 与资料检索、笔记状态、学习记录对接 |

### 5.1 推荐实施路线

**原型路线：Buzz＋Open WebUI。** 先验证转写质量、中文语音提问、材料问答和播报体验。该组合不是最终完整产品，也不代表已有精确引用回放。

**产品路线：科研工作台内开发研习伴模块。** 使用可替换的语音识别、语言模型和语音合成适配器，开发专用的共读界面和来源关联。原型通过后再确定哪些服务可以复用；不要求同时安装 Open WebUI、Open Notebook 和所有语音组件。

如果现有工作台改造成本过高，可先以独立服务提供模块 API，再通过宿主入口访问。决定前必须审查现有架构，不预设宿主已经具备所需接口。

### 5.2 模型与部署原则

- 优先兼容既有本地模型服务，例如 LM Studio；当前安装状态、模型和显存占用需重新检查。
- 语言模型、语音识别、语音合成及检索嵌入分别配置，不要求同一服务承担全部功能。
- “完全本地”要求所有处理组件均在本地运行；自托管网页仍可能调用云端接口。
- 不默认将学习资料发送给云端，不在本地服务失败后静默切换云端。
- 本地资源不足时限制并发、缩小模型或顺序执行；先测量，不提前承诺转写速度和对话延迟。
- 原型使用独立目录、数据和端口；开发前检查占用，避免与工作台现有服务冲突。

## 6. 系统结构与处理流程

### 6.1 功能分层

| 层次 | 职责 |
|---|---|
| 共读界面 | 资料导航、笔记编辑、选段提问、录音、回答、回放 |
| 应用服务 | 笔记本、导入任务、会话、学习记录、导出 |
| 来源与上下文服务 | 段落定位、转写关联、资料检索、引用校验 |
| 模型适配层 | ASR、LLM、TTS，可独立替换 |
| 存储层 | 原文件、转写、笔记版本、任务和会话元数据 |

### 6.2 材料处理流程

1. 导入原文件，记录校验值、文件类型和来源信息。
2. 对音视频建立转写任务；视频先提取音轨，保留与原视频的时间映射。
3. 保存逐段文字、起止时间、模型信息和原始输出。
4. 用户校对术语及数字，生成单独的校对版本。
5. 从明确选定的转写版本生成笔记草稿，要求附带原始段落标识。
6. 校验段落标识确实存在，保存笔记块与来源片段的关联。
7. 用户确认笔记后进入共读；原始文件与原始转写不被覆盖。

### 6.3 一次语音共读流程

1. 用户选择段落，按住说话；界面明确显示正在录音。
2. 松开后停止录音并识别，允许修改识别结果后发送。
3. 服务端收集当前笔记版本、选中段落、问题和近期会话。
4. 优先读取当前段落的来源，必要时检索当前笔记本的其他资料。
5. 模型生成解释，区分材料原述、推断、补充知识和待确认内容。
6. 服务端检查引用标识与定位信息；无效引用不得渲染为可信链接。
7. 展示文字答案，可选播报；引用点击后打开文档或播放原片段。
8. 用户可继续追问、保存疑问或预览笔记修订。

引用存在只说明来源可定位，不自动证明答案完全受该来源支持；需以样例评审检查是否真正支持结论。

## 7. 共读界面设计

桌面端建议采用三栏结构：左侧为笔记本与资料导航，中间为笔记阅读和编辑，右侧为共读对话。媒体播放器可放在中间区域底部。

必需交互：

- 当前选区高亮，发送前显示“正在讨论：某章节／某段落”。
- 没有选区时使用当前章节或整篇笔记，并在界面说明上下文范围。
- 录音期间可取消；发送前可修改文字；麦克风权限失败时仍能打字。
- 回答附来源卡片，区分笔记、原转写、文档和补充解释。
- 播报提供停止按钮；首次播放按浏览器要求由用户触发。
- “加入笔记”先显示修改预览，确认后新增版本。
- 新问题不会自动停止或删除已有后台转写任务。
- 初次使用只显示必要操作，模型和服务配置集中放在设置中。

## 8. 数据模型

优先使用宿主已有可靠存储；独立实现时可用 SQLite 存元数据、文件目录存媒体。第一版无需先搭建独立向量数据库。

| 实体 | 关键字段 | 说明 |
|---|---|---|
| Notebook | id、title、description、created_at | 一个实验或学习主题 |
| Source | id、notebook_id、type、path、hash、duration、status | 原始材料；文件同名不能作为唯一身份 |
| TranscriptRevision | id、source_id、parent_id、kind、model、created_at | 原始识别与人工校对版本 |
| TranscriptSegment | id、revision_id、start_ms、end_ms、text、speaker | 时间为原媒体时间轴；未知说话人可为空 |
| NoteRevision | id、notebook_id、parent_id、status、created_at | 草稿或用户确认版本 |
| NoteBlock | id、revision_id、heading、content | 可定位的笔记块 |
| EvidenceLink | id、note_block_id、source_id、segment_id、locator | 文本块与证据关联；locator 可保存页码和时间 |
| ChatSession | id、notebook_id、title、created_at | 共读会话 |
| ChatMessage | id、session_id、role、text、context_snapshot、citations | 保存当时笔记版本与选区，便于复查 |
| LearningItem | id、notebook_id、note_block_id、question、status、review_at | 疑问和复习状态 |
| Job | id、type、source_id、state、progress、error、attempt | 导入、转写、摘要等后台任务 |

### 8.1 数据约束

- 已被引用的转写和笔记版本应保留，编辑生成新版本。
- 缺少时间戳的外部文稿允许导入，但只提供文本定位，不虚构回放位置。
- 一个笔记块可关联多个片段；摘要重排后不依据段落序号猜时间。
- 删除材料前提示引用影响，优先可恢复归档。
- 模型不提供置信度时保留为空，不制造数值；有置信度也不直接视为事实正确概率。
- 导出 Markdown 附来源清单；跨机器迁移时需要同时迁移关联媒体和元数据。
- 用户语音提问默认保存识别文字，录音在处理完成后清理；可提供显式保留选项。

## 10. 回答规则与实验信息质量

1. 优先回答当前选区的问题，解释术语后再展开细节。
2. 原始讲解和用户确认版规程都要标注身份；二者矛盾时并列呈现并请求核对，不静默合并。
3. 区分材料直接记载与 AI 补充解释。第一版不自动联网搜索，用户可导入参考材料补充依据。
4. 浓度、体积、温度、时间等关键参数必须可追溯；缺失时明确写“材料未说明”。
5. 转写疑似错字可提出候选写法，但未经确认不得替换为既定事实。
6. 不确定用户所说“这里”指哪里时，在回答前请求明确段落。
7. 笔记、录音和导入文档中的指令视为资料内容，不能覆盖系统规则或触发任意工具执行。
8. 复述练习只依据指定材料评分，记录遗漏和理解差异，不给出独立实验资格结论。

## 11. 开发阶段与交付物

采用阶段验收驱动推进，暂不承诺日历工期；P0 完成后依据硬件、依赖和宿主改造量估算。

| 阶段 | 主要工作 | 交付物 | 完成条件 |
|---|---|---|---|
| M0：环境与样例验证 | 审查宿主接口、端口和资源；选择真实样例；比较转写效果；验证材料语音问答 | 环境清单、固定版本清单、样例结果、选型记录 | 明确可运行组合、关键误识别及未解决限制 |
| M1：材料与来源 | 笔记本、文件存储、任务队列、转写、校对、来源关联 | 可恢复的材料库与转写校对页 | 重启不丢数据，引用可定位原媒体 |
| M2：笔记与文字共读 | 草稿生成、编辑版本、选区上下文、文字问答、引用回放 | 可操作的共读页面 | 选段问题回答正确关联材料，引用有效 |
| M3：语音共读 | 按住录音、识别校对、回答播报、取消和异常处理 | 语音共读第一版 | 完整流程通过，语音失败不阻断文字功能 |
| M4：学习记录与交付 | 疑问状态、Markdown 导出、备份恢复、宿主入口和回归 | 研习伴 v0.1、使用文档、验收报告 | 第一版验收清单全部通过 |

## 12. 验收方案

### 12.1 样例集

准备至少三类材料：单人清晰讲解、中英文术语混合讲解、带噪声或多人插话的讲解。另准备一份有意保留缺失参数或矛盾描述的材料，用于验证系统不会自行补齐。

样例应包含人工核对的关键术语、数字与单位，以及至少 20 个共读问题。问题覆盖当前段落指代、连续追问、材料缺失、来源冲突和原音频定位。

### 12.2 必须通过的验收项

| 编号 | 验收项 | 通过要求 |
|---|---|---|
| A01 | 材料导入 | 支持范围内文件可处理；不支持或损坏文件有明确提示 |
| A02 | 任务恢复 | 刷新或重启不会静默丢任务，能恢复或明确标记可重试 |
| A03 | 转写校对 | 原始结果可保留，校对生成独立版本 |
| A04 | 选区理解 | 固定样例中的指代问题正确使用所选段落 |
| A05 | 来源完整性 | 固定样例所有展示的引用均能定位真实资料 |
| A06 | 回放位置 | 至少 10 个手工选取片段能回到相应讲解；记录实际时间偏差 |
| A07 | 缺失参数 | 缺失与歧义样例中不编造关键实验参数 |
| A08 | 回答依据 | 对 20 个问题人工复核，至少 18 个相关且得到所引材料支持；关键参数编造为零 |
| A09 | 语音异常 | 拒绝麦克风、取消、识别失败均可恢复并继续文字提问 |
| A10 | 播报控制 | 可停止，连续提问不会叠加播报 |
| A11 | 修改保护 | AI 建议未经用户确认不覆盖已确认笔记 |
| A12 | 持久化 | 重启后资料、会话、笔记与学习状态一致 |
| A13 | 备份恢复 | 从备份恢复一个完整笔记本并验证引用可用 |
| A14 | 本地模式 | 所有推理请求仅到配置的本地服务，无云端静默回退 |
| A15 | 宿主回归 | 工作台原有文献阅读、检索和其他已用功能不受影响 |

### 12.3 性能记录

在实际机器上记录模型、硬件、音频时长、转写耗时、内存／显存峰值、语音识别耗时、回答首字延迟及首段播报延迟。M0 建立基线后再确定可接受阈值；不能仅以某项目公开跑分作为本机性能承诺。

## 13. 风险与应对

| 风险 | 应对措施 |
|---|---|
| 实验术语、数字和单位识别错误 | 校对流程、术语表、保留原音频；优先验证关键参数 |
| 摘要造成来源关联丢失 | 从转写开始保存稳定标识，生成笔记时引用标识而非猜时间 |
| 有引用但引用不支持结论 | 自动校验定位存在性，并人工评估语义支持性 |
| 多模型争用显存 | 限制并发、任务排队、按需加载；实际测量后选型 |
| 连续语音开发量过大 | 第一版采用按住说话，连续通话后置 |
| 开源接口或许可证变化 | 固定版本并记录适配范围，升级前回归 |
| 自托管仍将数据送到云端 | 分组件展示处理位置，本地模式禁用外部回退 |
| 原型侵入既有工作台 | 独立端口与数据，先验证后接入，保留回滚方案 |
| 资料错误被当成标准答案 | 明确资料身份和确认状态，矛盾内容单独标注 |

## 14. 待确认事项及暂定方案

以下问题在对应阶段开始前确认；不阻碍原型规划。

| 待确认事项 | 暂定方案 |
|---|---|
| 最终形态 | 科研工作台模块，允许独立原型 |
| 主要使用设备 | Windows 桌面，手机端后置 |
| 本地或云端 | 优先本地；任何云端处理需用户选择 |
| 识别模型 | 用真实样例比较 faster-whisper 与 FunASR 后决定 |
| 语言模型 | 优先评估既有本地模型服务，不预设现有模型足够胜任 |
| 语音回答 | 支持但可关闭；本地中文 TTS 适配独立验证 |
| 第一版材料量和时长 | M0 统计，形成上传限制和任务资源预算 |
| 是否复制成品项目代码 | 默认通过接口复用；复制或改造前检查许可证 |
