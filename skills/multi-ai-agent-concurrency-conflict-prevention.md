# 多 AI Agent 并发执行防冲突设计

## 目标
把几十个 AI Agent 同时协调执行任务的系统当作分布式并发系统来设计，分层防止资源写冲突、任务重复分配、状态不一致、工具调用冲突、死锁/循环等待和通信风暴。

## 材料
- 多 AI Agent 并发执行系统（具体规模/框架待核对）
- 中心化调度器或主管 Agent
- 任务队列
- 子任务唯一 ID
- 锁或租约机制
- 共享资源（外部 API、文件、数据库等；具体资源待核对）
- 乐观锁/版本号
- 悲观锁或分布式锁
- 幂等件/唯一操作 ID
- 共享状态存储（Redis 或数据库）
- CAS 更新机制
- 状态变更时间日志
- 消息队列或发布订阅
- 消息去重 ID
- 结果队列
- 高风险操作审批队列
- Saga 补偿操作
- 子任务检查点
- 死锁检测机制（超时和依赖图）
- trace ID 与可观测性日志
- 监控指标：冲突率、重复执行率、死锁率、任务完成率、人工接管率

## 步骤
### 1. 任务层防冲突
- 操作：使用中心化调度器或主管 Agent，将大任务拆成子任务，放入任务队列；每个子任务设置唯一 ID；子 Agent 从队列领取任务，领取时加锁或使用租约。
- 参数：租约时长 30 秒；超时自动释放；其他调度参数待核对。
- 注意：避免同一个子任务被两个 Agent 同时领取；防止某个 Agent 卡死导致任务长期被占用。
- 检查点：同一子任务只被一个 Agent 领取；任务队列中无重复执行记录；超时任务能自动释放。

### 2. 资源层防冲突
- 操作：对共享资源加锁；读多写少场景使用乐观锁并加版本号，提交时检查版本是否变化；写多场景使用悲观锁或分布式锁；对支付、退款、发消息等幂等写操作加幂等件，每个操作设置唯一 ID，重复请求返回之前结果。
- 参数：锁超时时间待核对；版本号规则待核对；幂等件存储方式待核对。
- 注意：锁必须设置超时，防止死锁；重复请求不能产生重复副作用。
- 检查点：并发写同一资源时只有一个成功；重复请求返回相同结果；无重复支付、退款或消息副作用。

### 3. 状态层防冲突
- 操作：不要让每个 Agent 各自维护一份状态；使用共享状态存储，例如 Redis 或数据库；每次更新状态使用 CAS，即比较并交换；只有版本号匹配才能更新；更新成功后版本号加一；失败后重新读取最新状态再决定下一步；记录状态变更时间日志。
- 参数：共享状态存储类型待核对；CAS 字段/版本号格式待核对；日志保留时间待核对。
- 注意：两个 Agent 同时更新时，只有一个能成功；失败方必须基于最新状态重新决策，不能继续用旧状态。
- 检查点：并发状态更新只有一个成功；状态变更可回溯；Agent 间共享状态一致。

### 4. 通信层防冲突
- 操作：Agent 之间不要随意点对点乱发消息；使用消息队列或发布订阅；主管 Agent 发任务；子 Agent 订阅自己的任务类型；子 Agent 完成后把结果发到结果队列；主管 Agent 统一收集；消息加去重 ID；通信内容摘要化，不传完整对话历史；高风险操作走审批队列，不直接执行。
- 参数：消息队列类型待核对；去重 ID 规则待核对；摘要化字段待核对；审批队列策略待核对。
- 注意：防止重复消费；防止完整对话历史导致 token 爆炸；高风险操作不能绕过审批。
- 检查点：消息无重复消费；结果队列可被主管 Agent 统一收集；高风险操作有审批记录。

### 5. 恢复层防冲突
- 操作：当冲突仍发生时启用恢复机制；使用 Saga 模式，为每个步骤配置对应补偿操作；例如扣了库存则补偿加回库存，发了消息则补偿发一条更正消息；每个子任务设置检查点，失败后从检查点恢复；使用超时和依赖图进行死锁检测，发现循环等待时强制释放或升级到人工。
- 参数：检查点粒度待核对；补偿操作清单待核对；死锁检测超时阈值待核对；人工升级条件待核对。
- 注意：补偿操作必须与原始步骤对应；不能从头重跑所有任务；循环等待不能无限等待。
- 检查点：失败任务能从检查点恢复；补偿操作可执行；死锁能被检测并释放或升级人工。

### 6. 权限最小化与可观测性
- 操作：每个 Agent 只授予完成自身任务所需的工具和权限，不能越权；敏感操作要求人工审批；为每个 Agent 的每一步记录 trace ID，记录任务 ID、工具调用、参数、结果、资源获取和释放；监控冲突率、重复执行率、死锁率、任务完成率、人工接管率。
- 参数：权限清单待核对；trace ID 格式待核对；监控阈值待核对。
- 注意：不能给 Agent 过大权限；异常必须能定位到具体 Agent 和具体步骤。
- 检查点：Agent 无法执行越权操作；敏感操作有审批记录；异常可定位到具体 Agent、步骤和工具调用。

## 安全
本 skill 为多 AI Agent 并发系统设计方法，不涉及生物安全或废液处理；涉及外部 API、文件、数据库、支付、退款、发消息等高风险操作时，应执行权限最小化、敏感操作人工审批、日志审计、trace ID 追踪和异常监控。
