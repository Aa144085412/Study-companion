# JEV 快决策模型 vs 大语言模型

## 概览
JEV 是"快思考"型 agent 模型：一次前向计算就能根据当前状态做出一个决策，因此做决策比"一个词一个词往外蹦"的自回归大语言模型快许多倍；它擅长快速直觉判断，而非长程逻辑推演。

## 何时不要用
- 需要长程逻辑推演、写作、代码生成等"慢思考"任务时，应改用大语言模型，不要用 JEV。
- 需要精确数值/事实/可核验答案时，JEV 的直觉式快速判断不保证正确，需回原资料核对（本 skill 结论基于单条视频，未交叉验证）。

## 核心要点（先看这里）
- 同样是"做一个决策"：大语言模型必须**自回归**地一个词一个词生成（每生成新词都要把前面已生成的结果重新打包输入）；JEV 一次输出就能做出一个决策，因此快许多倍。
- 快的根因在**输出方式**：LLM 把计算结果硬设成固定大小的词表长度、用 softmax 算出每个词的概率再挑概率最高的词输出；JEV 则直接计算"每个可选项 × 当前状态"的得分，用 softmax 转成每个选项的概率，并**一次性**输出。
- JEV 的"可选项"信息大多由一个程序自动抓取（作者类比为"高级点的爬虫"）：后台实时读取电脑页面的状态、爬取页面上可点击的按钮，组装成结构化 JSON 发给 JEV，整个抓取非常快 → 在**决策效率**上 JEV 碾压 LLM。
- 快/慢思考类比（丹尼尔·卡尼曼《思考，快与慢》）：传统大模型＝**慢思考**（擅长逻辑推演、写作、代码）；JEV＝**快思考**（擅长快速直觉判断）。视频结论：未来两者结合或许才是 AI 的进化方向。

## 关键概念与名词
- 自回归（autoregressive）：每生成一个新词都要把之前已生成的结果重新打包输入，再生成下一个。
- softmax：把一组原始得分/分数转成一组和为 1 的概率。
- 词表（vocabulary）：LLM 输出时把计算结果硬设成的固定大小的候选词集合。
- 快思考 / 慢思考：《思考，快与慢》中的两种思维系统；此处用来类比 JEV（快）与传统大模型（慢）。
- JSON（结构化报文）：把"当前状态 + 可点击选项"组织成的机器可读结构，喂给 JEV。

## 知识要点（分主题）
### 大语言模型为什么慢
- 输出＝自回归：一次只出一个词，且每出一个词都要把前文重新打包输入。
- 每次输出把结果硬设成固定词表长度 → softmax 算每个词的概率 → 挑最高概率的词。
- 只能逐词往外蹦 → 面对需要快速决策的任务，效率非常低。

### JEV 为什么快
- 输出时不算"每个词的概率"，而是算"每个可选项 × 当前状态"的得分。
- 再用 softmax 把这些得分转成每个选项的概率，并**一次性**输出。
- 一次前向计算即可根据当前状态做出决策。
- 可选项信息由"高级爬虫"式程序在后台实时读取页面状态 + 爬取可点击按钮后组装成 JSON 提供。

### 快 / 慢思考类比
- 借鉴《思考，快与慢》：传统大模型＝慢思考（逻辑推演、写作、代码）；JEV＝快思考（快速直觉判断）。
- 展望：快思考与慢思考两种系统结合，或许才是 AI 的进化方向。

## 方法 / 流程（理解 JEV 决策链路）
1. 程序在后台读取电脑页面当前状态。
2. 爬取页面上所有可点击的按钮（可选项）。
3. 把状态 + 可选项组装成结构化 JSON。
4. JEV 对"每个可选项 × 状态"打分，softmax 转概率。
5. 一次性输出所有选项概率 → 选出当前状态下的一个决策。

## 常见误区 / 易错点
- 误区：JEV 比 LLM"聪明"。→ 正解：JEV 只是在**快速决策**这一维更快，不擅长长程推演/写作/代码；两者互补而非替代。
- 误区：JEV 能替代 LLM 做一切。→ 正解：快思考适合直觉判断、GUI/电脑操作等即时决策；慢思考任务仍用 LLM。
- 误区：模型名写作 GEV / JV / G1V。→ 正解：视频作者标题用「jev」，本 skill 记为 **JEV**（语音转写把该专名反复误听成多个写法）。
